The demo site, explained

A tiny site whose job is to prove the whole pipeline: its source is built inside a locked-down Docker box, and only the finished folder goes live.

1 From source to a live page

2 Before and after: the stamp

The source page has two placeholders. Only the build step can fill them in, so the finished page is proof that it was built, and by which Node.

source examples/static-site/src/index.html

<h1>static-site, built with __BUILT_WITH__</h1>
<p class="muted">built at __BUILT_AT__</p>

after the build dist/index.html

<h1>static-site, built with node v22.23.3</h1>
<p class="muted">built at 2026-10-11T15:37:34.896Z</p>
Why it matters. The server has no Node installed. If you see a Node version on the live page, it came from the container. If you ever see __BUILT_WITH__, the source was deployed by mistake, and the test treats that as a failure.

3 Releases: keep a few, move one arrow

What is the arrow, really? A symbolic link called current. Caddy serves whatever it points at, and replacing it is a single filesystem step, so a visitor sees the old release or the new one and never half of each.

4 The files

FileJob
examples/static-site/package.jsonnames the build command (npm run build) and the Node version wanted (engines.node)
examples/static-site/package-lock.jsonpins dependencies, so npm ci installs exactly the same every time
examples/static-site/build.jsthe build step: stamps index.html, copies the rest into dist/
examples/static-site/src/index.htmlthe page, with the two placeholders
examples/static-site/src/style.cssa copy of the shared pink theme
scripts/build.pyruns the Docker box and hands dist/ to the deploy

The Node version comes from engines.node, but only as a small number put into a fixed image name (node:22-slim). The raw text never reaches a command.

5 What the build box is not allowed to do

Be root

It runs as user 1000. A build cannot change system files.

Write to its own disk

The root filesystem is read-only. Only /app and a small temporary folder are writable.

Use special powers

All Linux capabilities are dropped and no new privileges can be gained.

Run away

1 GB of memory, 2 CPUs, 512 processes and 10 minutes. Then the box is removed.

See your secrets

.env files are never copied in, and the host’s environment is not passed.

Run install scripts

npm ci --ignore-scripts is the default. A package’s own install hooks do not run.

And if it does fail? A failed build, an empty dist/ or a dist that is a link all stop the deploy. The site keeps serving the previous release, and the last lines of the build output are written to the deploy log.

Try it

Run from the repo folder, inside WSL. Docker must be running.

# build in the box, then deploy
python3 scripts/build.py build demo-site examples/static-site
image: node:22-slim@sha256:c3de60bf...
built dist/ with node v22.23.3
live: 20261011-232150-008  (was: 20261011-232150-007)

# see the releases (the * is live), and go back if you want
python3 scripts/deploy.py list demo-site
python3 scripts/deploy.py rollback demo-site

Then open http://demo-site.localhost:8080 and look for the Node version in the heading.
