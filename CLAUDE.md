# mini-deploy: notes for agents

A small Netlify-style host, built in stages to **learn** how deploy platforms work: `git push` → webhook → build → new release folder → `current` link flips → Caddy serves the site.
Plan and diagrams: `Obsidian/Projects/claude add-ons/agent-patterns-and-deploy-platform.md`. Project note: `Obsidian/Projects/Mini Deploy/Mini Deploy.md`.

## Owner's working style

- **Teach + build.** For each step: explain the idea in 2-4 plain sentences, build it, then give the owner the test command to run themselves. Short "why" comments in the code.
- List and discuss changes first. Build only after the owner says **"go"**.
- One stage per session. Use `/stage N`.
- Never expose anything to the public internet (port forwarding, firewall rules, a real domain, tunnels) without the owner asking.
- Never install software without asking first (apt, Docker, Caddy, pip packages).

## Security rules (the reviewers check these)

- App names: `^[a-z0-9-]{1,40}$` only. Never build paths or shell commands from unchecked input.
- No `shell=True`; pass argument lists to `subprocess`.
- Webhooks: check `X-Hub-Signature-256` with `hmac.compare_digest` **before** reading anything else. Secret comes from an env var, never committed.
- Switch the `current` link atomically: `ln -sfn` into a temp link, then `mv -T`. Keep at least the last 3 releases for rollback.
- Secrets go in `.env` (gitignored). Never print them.
- Never publish links, special files, `.env*`, `.git`, `.npmrc`: `deploy.py` checks the source **and the private copy it publishes**. Release = at most 500 MB, setuid bits stripped.
- Builds run as uid 1000, read-only root fs, caps dropped, image pinned by digest, npm scripts off, `.env` never copied in. Same-app builds are serialized (`.build.lock`).
- Caddy's admin API is a root-only unix socket (`/run/caddy-admin.sock`), never TCP. Dotfiles are never served.
- Webhook (`scripts/webhook.py`): loopback only (config refuses anything else). Order: path, size (1 MB), raw body, `X-Hub-Signature-256` via `hmac.compare_digest`, and only then parse. Every failure is the same bare 401. App, branch, URL and sub-folder come from `config/webhook.json`, never the payload, with one exception: for a repo with `"previews": true`, the branch of a push to a non-main branch comes from the payload, is read only after the signature check, must pass `safe_branch()`, only reaches git as a list argument after `--`, and is never logged (only the site name made from it); `after` must be 40 lowercase hex; each `X-GitHub-Delivery` is acted on once (ids persist in `/var/lib/mini-deploy/deliveries`). A valid signature is not proof of freshness: the worker builds a commit only if it is still the branch tip (`git ls-remote`), and skips one that is already live. Whole request has a 20 s deadline and at most 16 handlers. Secret is `WEBHOOK_SECRET` in `/etc/mini-deploy/env` (mode 600, root, parsed by Python, never sourced as shell), popped from the environment so children never inherit it. After a rollback the app is on hold: webhook pushes are skipped and logged `held` until `deploy.py unhold <app>` (a manual deploy or build also lifts it). Opening the webhook to the internet (tunnel) is the owner's decision.
- Previews: site name `<branch>--<app>` from `deploy.preview_name()` (cleaned, plus an 8-hex hash of the real branch when cleaning changed it; 4 hex was collidable on purpose). The real branch is stored in `/sites/<preview>/.branch`; a build or delete for another branch is refused (`check_preview`, `remove_preview(name, branch)`). Only previews may contain `--`: `deploy.py deploy`, `build.py` and the webhook config refuse it in app names, and `deploy.py remove` accepts nothing else (checked 2026-10-12: no older app has `--`). At most 10 previews per app (only folders with `releases/` count; a failed first build's empty folder is removed by `drop_if_empty`), 2 releases each. Deletion: folder must exist, then `git ls-remote` (exact ref match, `remote_tip`) must show the branch is gone. Locks: always `.build.lock` before `.lock`; `locked` refuses if the folder was removed while it waited. Webhook queue: at most 20 different previews waiting (more get 503), live apps always taken first, a busy retry never replaces a newer job, `pending.json` that cannot be read is moved to `pending.bad`. **Owner decision (2026-10-12): with previews on, every branch pushed by anyone with write access is built and shown on the Wi-Fi; fine while the owner is the only one who can push. With collaborators, add a branch-prefix allowlist.**
- Every deploy, rollback and failure is one line in `/var/log/mini-deploy.log`. Release ids are UTC and always sort after existing ones.
- Tests never `rm -rf` inside scripts: they leave their `/sites/*-<pid>` apps and `/tmp/mini-deploy-*` folders, and the owner (or Claude, by a direct command) removes them.
- Tests never write into the real deploy log: unit tests point `deploy.LOG_FILE` at a temp file. (A fake `wa`/`wb` app once showed up on the dashboard as "needs a look".)
- Sites (`web/`): no external requests, no fonts or CDNs; dashboard JS uses `textContent` only (log lines hold build output); body text must reach 4.5:1 contrast (checked by `test-sites.sh`). `web/theme/pink.css` is the source; run `scripts/sync-theme.sh` after editing it. Caddy sends `Cache-Control: no-cache` so a deploy is visible at once.
